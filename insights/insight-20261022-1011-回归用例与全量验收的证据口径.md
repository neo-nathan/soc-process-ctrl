# 回归用例与全量验收的证据口径

**场景**:PL-02（名单页自带创建 / 编辑弹窗）用 `implement-plan` 执行。S-6 要验「公共弹窗 `#addNewListModal` 的标题、文字不受名单页影响」；TK-3 要求「TK-1、TK-2 都完成后按 §七 从头跑一遍」。证据见 `changelog/log-20261022-0535-实施PL-02.md`（「Task TK-1 内审第 1 轮」I1、「整体审」S2）、`implement/PL-02/`。

**现象 / 坑**:

1. 主 Agent 派 Tester 时把原句「不受名单页影响」写成「= 101 `layout.html` 原文」，比原句窄；Tester 指出后改成前后比较，但第一版用例只在弹窗**没打开时**记了快照。日志页打开公共弹窗时会自己改标题（「新建名单」→「新建白名单」）、改按钮 `data`，照这个用例跑必然误判红，内审判 important。
2. 只比打开态还不够：调用方打开时会重写一部分字段，被测页面留下的改动可能被盖掉，看不出来；要另比一组关闭态。
3. TK-3 全量验收时 S-6 没在 TK-3 时间段里重跑，只写了「指纹相同，结果有效」，整体审提醒外审会质疑「从头跑一遍」。

**结论**:

- 派活时「与改动前一致 / 不受影响」类原句一律原样转述为前后比较，不替 Tester 改写成「等于某个静态值」。
- 前值（S0）必须在进被测页面之前、经和后值（S1）**同一条正式入口**真打开采集；打开态、关闭态各比一组；静态字段另外对照原文。
- 全量验收复用某条用例的早先结果时，报告里写清三件事：那次运行晚于哪些改动完成、之后被测文件和库的指纹都没变、指纹的出处命令。

**检查清单**:

1. 回归用例的「前」值有采集步骤吗？和「后」是同一个入口吗？
2. 调用方打开时会改写被比较的字段吗？要不要加关闭态对比？
3. 全量验收里有没有复用早先结果的用例？时间先后和指纹证据写进报告了吗？
