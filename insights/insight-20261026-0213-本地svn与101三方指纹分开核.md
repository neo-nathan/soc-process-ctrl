# 本地、svn、101 三方是否一致要分别核指纹

**场景**：2026-10-26，名单页 9 个文件注释精简后已传 101 并核过指纹（本地 = 101）。之后用户自己手动提交了 svn r72065。证据：`changelog/log-20261025-2316-名单页源码注释精简.md` 文末两段追加、`changelog/log-20261026-0203-删除名单页mock.md`「怎么验证」。

**现象 / 坑**：

- 核实 svn 时只跑了 `svn log` 和 `svn st`，看到工作副本没有改动，就推断「svn 里就是上次核对过与 101 一致的版本」，并写进了状态页和 changelog。
- 实际情况是用户提交前删了 8 个文件的头部注释：本地 = svn，但本地 ≠ 101。直到下一个任务开工核指纹，才发现 `list.js` 是 `d9f500c6`，不是记录的 `30b427f5`。

**结论**：

- `svn st` 干净只能证明本地 = svn。本地 = 101 要另外核，以当场在两边算出的指纹为准，不能沿用之前记录的指纹。
- 用户说「我已经手动提交」时，默认本地文件可能变过，先核一遍指纹，再更新状态页。
- 指纹不一致时，用 `implement/comment-cleanup/strip-equiv.js` 去掉注释比代码：SAME 说明只改了注释，DIFF 说明代码也变了，要先问清楚再上传。
- 状态页里写的「一致」，必须附上当次实算的指纹和时间。

**检查清单**：

1. 状态页或 changelog 要写「A 与 B 一致」：两边的指纹是不是这次当场算的？
2. 用户手动操作（提交 svn、改文件）之后：本地指纹和上次记录还一样吗？
3. 本地和 101 不一致：去注释后比较是 SAME 还是 DIFF？DIFF 先问用户。
