# 共享机器禁止试错口令，登录重试只对中心开

**场景**：PL-05 全链路测试，`e2e/lib/ssh.js` 加「登录失败重试」时，为了验证「口令错时重试 3 次后返回」，Agent 拿 13.220（同事在用、本计划只读）跑了错口令。证据：`changelog/log-20261104-0016-实施PL-05.md`「13.220 登录被锁事故」一节。

**现象 / 坑**：3 次错口令后，正确口令也被拒（`sshpass` 退出码 5），随后查实 13.220 开着 `pam_faillock`（`deny=3 even_deny_root unlock_time=60`），root 被锁约 60 秒后自动解锁，失败记录留在 `faillock --user root` 里（清除要写终端，只读约定下不动）。没改数据，但留下了失败记录、可能短时锁住 root，影响同事。另一个现象：14.15 在连接很密时偶尔拒一次正确口令，隔几秒就好。

**结论**：
- 「错口令」类测试只在本机 sshd 或自己能负责的机器上做，绝不对共享环境（终端、101、14.15）试错。
- 自动重试只对确认会偶发拒绝、且口令确定正确的中心开；终端一律不重试，口令真错时重试会叠加失败次数。
- 一旦怀疑锁定：停止连接该机器，先等一会（锁定时长各机器不同，13.220 是 60 秒，保守等 10 分钟）再只试 1 次正确口令，并如实记进 changelog 和问题清单。

**检查清单**：

1. 要测登录失败逻辑？目标机器是不是共享的？是 → 换本机或不测。
2. 重试代码有没有限定主机？终端是否排除？
3. 出现过登录失败后，有没有在 changelog 记时间、次数、影响和恢复结果？
