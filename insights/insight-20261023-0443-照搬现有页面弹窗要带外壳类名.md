# 照搬现有页面弹窗要带上它的外壳类名，别手抄样式

**场景**：名单页「应用到组」弹窗照策略中心 `#setGroup` 复制 HTML（`list.html`），样式当时按 PL-01 F-11 从 `assetbehaotherstra.css` 挑着手抄进 `processManageList.css`。10-23 用户截图对比发现勾选框、对齐、底边、横向滚动条都不一样（`changelog/log-20261023-0441-应用到组弹窗样式对齐策略中心.md`）。

**现象 / 坑**：

1. 策略中心样式的选择器以 `.strategy_content`（页面外壳）、`.policy-form` 或 `#setGroup` 开头，换个页面全部失效；HTML 一模一样也没用。
2. 手抄只抄了「看起来相关」的那组（`.tree_type_noe .ztree …`），漏了别处的同名作用域规则：`.strategy_content .ztree li` 行高 26px（`assetbehaotherstra.css` 3375-3410）、`.policy-form input[type=checkbox]` 图片勾选框（`index.css` 1243-1290）、`.strategy_content .ztree .ztree-node-checkbox`（`index.css` 11853）。
3. 文案变长（提示文字折成两行）会把固定高度弹窗的按钮挤出底边，看起来像「没有底边」。

**结论**：

- 搬现有弹窗时，在弹窗外面套一层同样的外壳类名（这里是 `<div class="strategy_content policy-form">`），让原规则直接生效；只补绑在原弹窗编号上的规则（编号换成自己的，权重保持相同）。
- 外壳类名自身常带整页用的样式（`.strategy_content` 有 `margin: 0 20px`、`min-width: 1000px`、白底），要用自己的类抵消，否则撑宽页面。
- 套之前 grep 全站 JS 有没有用这个外壳类名绑事件（`.strategy_content` 只有策略中心自己 3 个脚本用）。
- 不要把弹窗编号改成和原页面相同（`#setGroup` 有 16 处 JS 引用）。

**检查清单**：

1. `grep -rn '<外壳类名>\|<原弹窗编号>' public/esm/css` 看原样式都挂在什么选择器上。
2. 外壳类名自身的规则（`^\.外壳 *{`）有没有宽度、边距、背景要抵消？
3. grep JS 里有没有用外壳类名的代码会在本页加载？
4. 上 101 两边打开弹窗，用同一段脚本量：弹窗与按钮区底边、树行高、图标高与对齐、勾选框外观 / 背景、树区 `scrollWidth`/`clientWidth`；逐项对表。
5. 文案改长时看按钮区底边是否超出弹窗底边。
