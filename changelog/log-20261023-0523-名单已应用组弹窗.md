# 名单已应用组弹窗

- 时间：2026-10-23 05:23 EDT
- 触发：用户要求名单列表「应用范围」列也能像策略中心那样点「组【N】」弹出「已应用组」，接口用 `Procmanager/showUsedGroup`；评估后用户选「名单页自己写弹窗、已下发/未下发先不做点击」。

## 改了什么

SOC 源码（`ESMCenterST/public/esm/`，均未 svn 提交）：

- 新文件 `view/processManage/bwlistUsedGroup.js`：已应用组弹窗模块，对外 `bind` / `open` / `release`。表格配置照策略中心 `strategy/createTable.js`（每页 10、高 340），列照 `strategy/colums.js` 的 `groupList`（序号 / 组名称 / 终端数量 / 应用时间 / 已下发 / 未下发）；「已下发 / 未下发」只显示绿 / 红数字、不能点；「已下发」表头悬停说明发布后会先清零。查询从第 1 页查；`r.code` 非 0 时弹后端原因。
- `view/processManage/list.html`：新增弹窗 `#procmSeeGroup`（照抄 `seeGroup.html`，id 改 procm 开头，去掉策略中心的 JS 挂钩），外套 `.strategy_content.policy-form.procm-set-group-scope`。
- `view/processManage/list.js`：引入新模块；「应用范围」列的「组【 N 】」加 `js_procm_seegroup`（可点、悬停提示）；点击拦冒泡、不展开行；`openSeeGroup`；`destroy` 里 `release`。
- `css/processManageList.css`：照抄策略中心绑在 `#seeGroup` 上的几条（编号换成 `#procmSeeGroup`）；已下发 / 未下发颜色；「组【 N 】」手型；抵消 `.c-page-content` 下公共表格样式带来的单元格左内边距 16→12、分页栏内边距。

本仓库：设计文档 01 版本记录、7.5、8.5、第 9 节接口表、新增 9.1.8、12.1 P24 ⑧ 补注和新增 ㉑。

## 为什么

- 策略中心 `strategy/seeGroup/seeGroup.js` 不能直接复用：接口地址写死成 `Policycenter/showUsedGroup`；从每行 `data-row` 取编号，名单列表没有；下钻 `Policycenter/getEpIssuedStatus` 的产品对照表没有 PROCM，数会对不上；它被策略中心和 9 个产品策略页共用，且 `#seeGroup` 会留在公共布局 `#seeGroupBox` 里，名单页用同一 id 会撞。
- 101 后端 `Procmanager/showUsedGroup`（北京 10-23 17:01 版）已实现，返回字段兼容策略中心列定义；终端数按名单系统类型、装了 PROCM 过滤。
