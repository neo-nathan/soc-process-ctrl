# 应用到组弹窗样式对齐策略中心

## 改了什么

SOC 源码（`ESMCenterST/public/esm/`）：

- `view/processManage/list.html`：弹窗 `#procmSetGroup` 外面包一层 `<div class="strategy_content policy-form procm-set-group-scope">`；「应用组：」后面的提示文字删掉（原「没有名单的组，组内终端不按名单判断；新建子组会自动带上父组的名单」）；注释说明原因。
- `css/processManageList.css`：删掉原第七节末尾手抄的应用到组样式（树字号颜色、展开箭头、组图标、悬停、「继承」字样等约 100 行）；只留两部分：
  - `.procm-bwlist .procm-set-group-scope`：抵消 `.strategy_content` 自带的 `margin: 0 20px`、`min-width: 1000px`、白底（字体不抵消，策略中心弹窗也继承）。
  - 策略中心绑在 `#setGroup` 编号上的规则（`assetbehaotherstra.css` 2802-2847、2945-2948、2986-2994），原值照抄、编号换成 `#procmSetGroup`，权重与原规则相同，压得住 `.strategy_content .set_strategy`（宽 880）和 `.strategy_content .modal_type_one`（左偏 -420）。
- 设计 01：版本记录加一条；7.5「弹窗外壳」「提示文字」两行、「继承」样式那句改写。

## 为什么

用户发现名单弹窗和策略中心弹窗样式不一致（勾选框、对齐、底边、横向滚动条）。查明两边 HTML 几乎相同，差别在样式生效范围：策略中心样式的选择器以 `.strategy_content`、`.policy-form` 或 `#setGroup` 开头，只在策略中心页面生效；名单页以前手抄了一部分，漏了 `.strategy_content .ztree li` 行高 26px 那组（`assetbehaotherstra.css` 3375-3410）、`.policy-form input[type=checkbox]` 图片勾选框（`index.css` 1243-1290）、`.strategy_content .ztree .ztree-node-checkbox` 边距（`index.css` 11853）。用户选推荐方案：套外壳类名，不继续手抄、不改弹窗编号为 `#setGroup`（16 处 JS 引用，易冲突）。
