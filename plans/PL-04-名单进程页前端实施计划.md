## 三、接口用法与前端检查

### 3.1 页面调的接口（全部真接口，经 `RsCore.ajax`，入参一律传对象）

| 用途 | 地址 | 入参 | 页面怎么用返回 |
|---|---|---|---|
| 进程行 | `Procmanager/showWBList` | `{pid, policytype}` | `data.rows` 经 `bwlistAdapter.toProcList` 转换、排序、筛选（§4.1） |
| 信息条（Q2） | `Procmanager/getWBList` | `bwlistAdapter.toQuery(type, 空条件)`（= `policytype` + `timeRange=0`） | 找 `PID` 等于当前名单的那一行，`bwlistAdapter.toRow` 转换后画信息条；**找不到**（名单被别人删了）→ 回到列表；只有同一次 `showWBList` 成功时才另弹 `RsCore.msg.warn`「名单不存在或已被删除」（`showWBList` 回 code 3 时 core.js 已弹过「名单不存在。」，不再弹第二次） |
| 添加 | `Procmanager/addProcToWBList` | `{pid, policytype, propath, filehash, algo}`：路径去首尾空格；哈希去首尾空格、转小写；`algo` 按长度传 0 / 8 | 成功后重取（§3.2） |
| 移除 | `Procmanager/delProcFromBW` | `{pid, policytype, ids: 'ID'}` | 同上。ACL 补上前会被拒（F-2）：全局钩子弹一句「抱歉，您没有访问该接口的权限」，页面失败回调照常被调（解开处理中），页面不另弹 |
| 恢复 | `Procmanager/resProcFromBW` | `{id: 这一行的 ID, policytype}`（12:19 版只收单条，不带 `pid`，F-1 ④） | 同上 |

- 接口地址写在 `bwlistProc.js` 顶部常量里；后端字段再变，只改 `bwlistAdapter.js`（PL-03 R-1 同一做法）。
- 失败一律由 core.js 弹提示（code 1 弹「系统异常,请联系管理员！」；403 ACL 拒绝由全局钩子弹一句 warn，F-2；其他非 0 弹「错误」+ 后端原因，PL-01 F-12），页面的失败回调不再弹第二次。
- `bwlistMock.js` 不改：它只拦应用到组的 2 个地址，上面 5 个都原样放行。

### 3.2 什么时候取数

- 进入进程视图、点信息条右侧「刷新」、添加 / 移除 / 恢复成功后：**同时**发 `showWBList` 和 `getWBList`，两个都回来再一起重画（表格 + 信息条）；任一失败，表格不卡在加载中，已有内容保留。
- 每次取数带序号，只认最近一次的返回；离开进程视图（返回列表、离开名单页）后回来的结果丢掉。
- 重画时筛选条件保留；当前页超出总页数时退到最后一页。

### 3.3 前端查重（D-3；后端规则见 F-1 ②、F-12）

点「添加」时，用当前名单**全部**进程行（`showWBList` 最近一次返回，筛选前）查重：

- 规则键 = `ALGO` + 小写哈希 + 路径。路径按系统类型比较：Linux 原样（区分大小写）；Windows（Q7）不分大小写、`/` 与 `\` 当同一个（照 demo `normPath`）。
- 撞上 `STATUS` 0 / 1 的：红字「名单里已有路径和哈希都相同的「X」，不用重复添加」；撞上 `STATUS` 2 的：「名单里已有路径和哈希都相同的「X」，它已被标记移除，点它的「恢复」即可」（X = 那一行的进程名，文案照 demo `:779-781`）。都不发请求。
- 前端放行、后端仍拒的情况：只差大小写的 Linux 路径（F-12）→ 后端 code 7「该进程已存在。」由 core.js 弹出，弹窗留着（R-8）。

### 3.4 前端「至少保留 1 个」（D-3；需求原文第 4 条、设计 7.3）

点「移除」（普通进程和新增进程都查）时：

- 发布过 = 当前名单进程行里有 `STATUS` 为 0 或 2 的行（F-3 等价性；不看名单状态，避免被后端那处错带偏，例如 PID 38 状态是「有变更」但没发布过）；
- 发布过，且「`STATUS` 不为 2 的行数 − 1」< 1 → `RsCore.msg.warn`「白名单至少要保留 1 个进程，不能把进程全部移除；要清掉这条白名单请直接删除它」（照 demo `:696`，「白名单」按 `cfg.name` 换），不发请求；
- 没发布过的名单可以删光（删完后端状态回到 1 空白名单，信息条显示 `--`）。

### 3.5 前端添加校验（照 demo `:766-783`，按 `EPTYPE` 分支）

按顺序，第一个不通过就红字显示在弹窗里、不发请求：

1. 路径空 →「请填写进程路径」；
2. 路径（去首尾空格）超过 500 字 →「进程路径不能超过 500 个字符」（demo 没有，后端列宽 `varchar(500)`；单列一句，免得落到下一条格式提示，v0.1 审查建议 7。后端按字节算，含中文的路径前端放过、后端仍可能拒，F-14）；
3. 路径格式不对（Linux：以 `/` 开头且最后一段不为空；Windows：`/^[A-Za-z]:[\\/]/` 且最后一段不为空）→「Linux/信创 名单请填写完整的进程路径，示例：/usr/bin/python3」（Windows：「Windows 名单请填写完整的进程路径，示例：C:\Windows\System32\svchost.exe」）；
4. 哈希空 →「请填写文件哈希」；
5. 哈希不是 32 或 64 位十六进制 →「文件哈希应为 32 位（MD5）或 64 位（SHA256）十六进制字符」；
6. 查重（§3.3）。

## 五、页面行为（照 demo；偏离处说明原因）

### 5.1 进出

- 名单列表展开行点「进程」→ 名单页里换成进程视图（Q1）：最左「返回」按钮 + 面包屑「进程管控 / 白名单 / 名单名 / 进程列表」（黑名单页写「黑名单」）。点「返回」或面包屑「白名单」→ 回到列表（§4.1 `onBack`）；点「进程管控」→ 概览。
- 进入时信息条先用列表这一行画，取数回来后按 §3.2 重画。
- 在进程视图里离开名单页（点左侧菜单等）：`list.js` 的 `destroy` 先 `bwlistProc.release()`。`release` 要做：关添加弹窗（遮罩在 body 上）；销毁进程表格（含列宽拖拽，如果用了）；销毁日期选择器、清掉它挂在 body 上的弹层（照 `list.js:1447`）；销毁下拉美化（selectric，如果用了）；解绑本视图的全部事件（命名空间 `.procmProc`，含 `$(window)` 上的 `resize.procmProc`）；作废取数序号，让没回来的请求结果被丢掉。`release` 可以重复调、没打开过也能调。

### 5.2 信息条

- 发布状态：圆点 + 文字，颜色同列表页（`procm-st0～3`：灰 `--` / 蓝 待发布 / 绿 已发布 / 橙 有变更）；悬停说明用列表页状态说明框的 4 句（`list.html:118-125`，demo 只有 2 句，F-9），名单叫法从 `cfg.name` 取。
- 系统类型：`EPTYPE` 1 Windows、2 Linux/信创。
- 进程数：`PROCNUM`（`toRow` 换算，口径同列表）+ 有新增时绿色 `+N`、有待移除时红色 `-M`；点 `+N` = 变化状态选「新增」，再点取消；`-M` 同理。
- 应用范围：`GROUPNUM` 个组 `EPNUM` 台终端（终端数后端没有，先是 0，同列表页）。
- 创建时间。右侧：刷新（§3.2）。
- 信息条上的状态以后端为准（Q2），没发布过、有新增的名单显示「有变更」（F-3 那处错），和列表页一致，不在前端修正（R-3）。

### 5.3 工具栏、高级查询、表格

- 工具栏左「添加进程」，右「高级搜索」（展开 / 收起）。
- 高级查询照 demo、写法照名单列表页（点选项点了立刻筛；指定日期、关键字点「筛选」才生效；开始日期晚于结束日期时红字提示、不筛；「重置」清空全部；日期选择器同列表页，「今天」按北京时间）：时间范围（按添加时间）、变化状态、字段（进程路径 / 文件哈希）+ 关键字。有条件时显示「已筛选出 X 条，共 Y 条」。换条件回到第 1 页。
- 表格用 bootstrapTable，**前端分页**、每页 15 条，列设置同名单列表页：进程名称（+「新增」绿标签 / 「移除」红标签）、文件哈希（前面灰色算法小标签，悬停「算法：哈希」）、进程路径、添加时间、操作（新增和普通进程「移除」，待移除进程「恢复」）。待移除行浅红底、名称删除线、文字变灰。
- 标签悬停：「新增」=「上次发布之后新加入的进程，回白名单列表点「发布」后，终端才会放行」（黑名单页：「…回黑名单列表点「发布」后，终端才会拦截」）；「移除」见 Q4。
- 空结果：名单里一条都没有时「名单里还没有进程，点「添加进程」添加」；有进程但筛不出时「没有符合条件的进程」。
- 所有用户数据（路径、哈希、名单名）转义后输出。

### 5.4 添加

- 弹窗 `#procmProcAddModal`（外壳照名单页其他弹窗）：进程路径 *、文件哈希 *、进程名（边输路径边取最后一段，只读）、哈希算法（边输哈希边认：MD5 / SHA256 /「识别不出（应为 32 位或 64 位十六进制）」，只读）；底部说明「进程名、哈希算法自动识别；终端按「路径 + 哈希」识别要放行的进程，两者都相同才算重复」（黑名单页「放行」改「拦截」）。每次打开都是空表单。

### 5.5 移除、恢复

- 都不弹确认（demo）。移除前按 §3.4 检查。
- 通过后调移除接口（`ids` = 这一行的 `ID`）或恢复接口（`id` = 这一行的 `ID`）；成功后重取，不弹成功提示（demo 没有）；失败 core.js 弹原因（ACL 没补时是全局钩子弹的一句「抱歉，您没有访问该接口的权限」，F-2）。同一时刻只处理一个操作，处理中再点不响应。

### 5.6 防撞名（F-11）

- 进程视图的 JS 钩子类一律用 `js_procm_proc_` 开头，表格 id 用 `procmProcTable`，弹窗、日期输入框等 id 用 `procmProc` 开头，事件命名空间 `.procmProc`，都挂在进程视图自己的容器 `.js_procm_procpane` 上。
- 不复用列表页的任何钩子类和 id（如 `js_procm_chips`、`js_procm_search`、`#tbClient`），保证点进程视图里的东西不会触发列表页的处理，反之亦然。
