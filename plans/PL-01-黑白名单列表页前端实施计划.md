## 四、mock 接口约定（后端完成后按实际微调）

### 4.1 总体做法

- **一个开关**：`bwlistMock.js` 顶部 `ENABLED = true`。后端完成后改成 `false`，页面直接走真接口，业务代码不改。
- **一个拦截点**：名单页打开时 `install()`，临时包一层 `RsCore.ajax`，**只拦截下面 4 个地址**，其他请求原样放行；离开页面（`destroy`）时 `uninstall()` 还原。分组树组件内部发的请求也能被拦到，所以公共组件一行不改。
- 表格用 bootstrapTable 的 `ajax` 选项，请求也走 `RsCore.ajax`，同一个拦截点。表格组件交给 `ajax` 选项的请求对象带 `success` / `error` / `complete` 三个回调（`esm/dep/table/bootstrap-table.js:1928-1966`），而 `RsCore.ajax` 只在 `code=0` 时回调：所以成功时要把结果包回 `{r, data}` 交给 `success`，失败时调 `error`，两种情况都要调 `complete`，否则表格一直转圈。
- **数据来源 = 真名单 + 假字段**：mock 先用包装前的原始 `RsCore.ajax` 调真的 `getWBList` 拿到真名单（PID、名称等都是真的），再按 PID 算出固定的假字段，然后做高级查询。这样创建、编辑、删除走真接口后，列表能立刻看到变化。
- 发布、应用到组的结果存在页面内存里（按 PID 记），表格刷新后还在，**整页刷新后恢复原样**，不进数据库。
- 另有 `MODE = 'fake'` 可选：完全用假数据（照 demo 的 10 种情形，但系统类型全改成 Linux/信创、创建人全改成 optAdmin，照设计 8.8 第 6、13 条），用于演示全部状态。假数据的 PID 在库里不存在，编辑、删除会返回「名单不存在」，属正常。

### 4.2 列表 `Procmanager/getWBList`（接口已存在，补字段和查询条件）

**入参**（POST 表单，空值 = 不限）：

| 参数 | 取值 | 说明 |
|---|---|---|
| `type` | 2 / 3 | 必填；2 白名单、3 黑名单（已有） |
| `systype` | 空 / 1 / 2 | 系统类型：1 Windows、2 Linux |
| `ctime` | 空 / `7` / `30` / `month` | 创建时间快捷项：近 7 天 / 近 30 天 / 本月 |
| `cfrom`、`cto` | `YYYY-MM-DD` | 指定日期范围（含首尾两天）；任一不为空时忽略 `ctime` |
| `pubstatus` | 空 / 0 / 1 / 2 / 3 | 发布状态：0 `--`、1 待发布、2 已发布、3 有变更 |
| `scope` | 空 / 1 / 0 | 应用范围：1 已应用（组数 > 0）、0 未应用 |
| `delta` | 空 / `add` / `del` / `none` | 进程变更：有新增 / 有移除 / 无变更（新增、移除都为 0） |
| `kw` | 字符串 | 名单名称关键字，包含匹配，不分大小写 |

**出参**：`data = {rows, total}`，`total` = 筛选后的条数；**不分页**；按创建时间**升序**（照 demo）。每行在现有字段之外新增：

| 字段 | 含义 | 设计依据 |
|---|---|---|
| `PROCNUM` | 已发布版本的进程数（base） | 7.1、8.5 |
| `ADDNUM` | 还没发布的新增数（+N，名单进程表 `STATUS=1`） | 7.1 |
| `DELNUM` | 还没发布的待移除数（-M，`STATUS=2`） | 7.1 |
| `PUBSTATUS` | 发布状态 0～3（同上） | 7.1 |
| `GROUPNUM` | 应用到的组数 | 7.5 |
| `EPNUM` | 这些组里装了进程管控的终端数 | 7.5「应用范围」口径 |

### 4.3 发布 `Procmanager/publishWBList`（新接口，建议名）

- 入参：`pid`、`policytype`（2 / 3）。
- 出参：成功 `code=0`，`msg` = 「已发布，组内终端下次心跳（默认 5 分钟内）生效」；没有应用范围时 `msg` = 「已发布，应用到组后下发」（设计 8.8 第 12 条）。
- 后端规则：设计 7.2、7.4（只有待发布、有变更能发，发布后进程数必须 > 0）。
- mock：先按 7.2 校验（状态既不是待发布也不是有变更，或发布后进程数为 0，都不允许），不通过就返回非 0 的 `code` 和原因，和后端 `notice` 一样；通过就把该 PID 记成 `PROCNUM = PROCNUM + ADDNUM − DELNUM`、`ADDNUM = DELNUM = 0`、`PUBSTATUS = 2`。

### 4.4 应用到组：取已选组 `Procmanager/getWBListUsedGroupId`（新接口，建议名）

- 入参：`pid`、`productid`、`eptype`（分组树组件固定这样发，F-11）。
- 出参：`{aUsedGroupId: [{OBJID, ISLOCK}], aLockGroupId: []}`，格式同 `Policycenter/getUsedGroupId`。
- mock：返回内存里该 PID 记下的组；没有就是空数组。

### 4.5 应用到组：提交 `Procmanager/setWBListGroups`（新接口，建议名）

- 入参：`pid`、`policytype`、`aObjId[]`（勾选的全部组）。
- 出参：成功 `code=0`，`msg` = 「应用成功，组内终端下次心跳（默认 5 分钟内）生效」。
- 后端规则：设计 7.5（只有已发布能改；自动替换组上原有的名单；提交后重建组缓存）。
- mock：先校验状态是「已发布」，不是就返回非 0 的 `code` 和原因；通过就记下该 PID 的组，`GROUPNUM` = 组数，`EPNUM` 用组数乘一个固定系数假算。

### 4.6 已有接口（真调，不 mock）

| 接口 | 页面用途 | 入参 |
|---|---|---|
| `Procmanager/createWBList` | 创建 | `pname`、`description`、`policytype`、`systype`（不传 `procsource` / `proclist` = 只建名单） |
| `Procmanager/editWBList` | 编辑 | `pid`、`pname`、`description` |
| `Procmanager/delWBList` | 删除 | `pid`、`policytype` |

新增的 3 个接口需要后端补 ACL 登记（角色同现有 `['2','8']`）；mock 在发请求前就拦下了，现在不需要登记。

## 五、页面行为（照 demo，偏离处按设计 8.8）

- **页面布局**：沿用旧骨架的做法，隐藏顶部页签和左侧组树（`.c-page-nav`、`.c-page-silder`），内容区占满（`list.js` 现有 `init` 前几行）。
- **面包屑**：进程管控 / 白名单（黑名单）。
- **工具栏左**：系统类型筛选（全部 / Linux/信创；一期只有 Linux）、「创建白名单（黑名单）」按钮。**右**：高级搜索、刷新、列设置（bootstrapTable 自带的刷新、列设置）。
- **高级查询**：照 demo 四行点选（创建时间、发布状态、应用范围、进程变更，点了立刻查）+ 指定日期 + 名称关键字（点「筛选」才查）+「重置」；控件照 `log.html` 现有的 `#customSearchBox` 写法，日期用现有 `datetimepicker`。
- **列**：展开箭头 / 序号 / 名称 / 系统类型 / 进程数（base、+N 绿、-M 红）/ 应用范围（`N 个组 M 台终端`，没有为 `--`）/ 发布状态（圆点 + 文字，颜色：`--` 灰、待发布 蓝、已发布 绿、有变更 橙；表头和单元格悬停有说明）/ 创建人 / 创建时间 / 描述（超长省略，悬停看全文）。
- **折叠**：点行（或箭头、名称）在下面插一行按钮，同时只展开一行，再点收起（照 `openLine.js` 的交互）。
- **展开行按钮**：编辑 / 进程 / 应用到组 / 发布 / 删除。**不放「应用到终端」**。灰色按钮悬停说明原因，规则照设计 7.2：

| 发布状态 | 发布 | 应用到组 | 编辑、删除 |
|---|---|---|---|
| `--` | 灰：空名单不能发布 | 灰：先添加进程并发布 | 可 |
| 待发布 | 可 | 灰：先发布 | 可 |
| 已发布 | 灰：没有变更 | 可 | 可 |
| 有变更 | 可（发布后进程数 > 0；否则灰：至少保留 1 个进程） | 灰：先发布 | 可 |

- **进程按钮**：本期只放按钮，点了提示「名单进程页下一步开发」（Q3）；进程数里的 +N / -M 本期不做链接。
- **创建**：复用公共弹窗，标题「创建白名单（黑名单）」，系统类型固定显示 Linux/信创；成功后刷新本页表格。
- **编辑**：复用同一个弹窗，标题「编辑白名单（黑名单）」，带出原名称和描述，系统类型只显示不可改；调 `editWBList`。
- **发布**：确认弹窗「确定发布「X」吗？发布后进程数为 K。」；已应用到组的多一句「组内终端下次心跳（默认 5 分钟内）生效」，没应用的多一句「发布后才能应用到组」。
- **删除**：确认弹窗「确定删除「X」吗？删除后不能恢复。」；已应用到组的多一句「该名单已应用到 N 个组、M 台终端。删除后，这些终端下次拉取策略时会清掉本地名单（在线终端默认 5 分钟内，离线终端上线后）」（设计 7.6、8.8 第 2 条）。
- **应用到组**：只有「已发布」能点；弹窗照策略中心 `#setGroup`，`showInheritBtn:false`；提示文字「没有名单的组，组内终端不按名单判断；新建子组会自动带上父组的名单」（设计 7.5）；勾选为空且原来也为空时直接关闭不请求（照策略中心）。
- **底部统计**：名单总数 = 当前结果条数；进程总数 = 各行 `PROCNUM + ADDNUM − DELNUM` 之和。
- **空结果**：「没有符合条件的白名单（黑名单），可以调整条件或点"重置"」。
- 二次认证：不做（Q1）。
