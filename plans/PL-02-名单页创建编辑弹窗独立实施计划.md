## 四、`bwlistModal.js` 对外接口（实现细节由 Executor 定，接口照这里）

RequireJS AMD 模块，模块名 `processManage/bwlistModal`，只用 ES5。导出 3 个函数：

| 函数 | 什么时候调 | 做什么 |
|---|---|---|
| `bind($view)` | 名单页 `init` 渲染完 `list.html` 之后 | 记下页面容器，在容器上用事件委托绑「取消」「创建 / 保存」、弹窗 `hidden`（命名空间用 `.procmListModal`，不与 `list.js` 现有的 `.procmList` 混用）；先 `off` 同命名空间再绑，重复调用不会重复绑定 |
| `open(opts)` | 工具栏「创建…」、展开行「编辑」 | 按 `opts` 填好弹窗并显示；返回 `true` / `false`（弹窗不在页面上或参数不对时 `false`，`list.js` 照旧提示「弹窗没有加载成功，请刷新页面后重试」） |
| `release()` | 名单页 `destroy` 里 | 弹窗开着就关掉（去掉 body 上的遮罩），清掉上下文；之后回来的请求不再动页面 |

`open(opts)` 的参数（和 PL-01 TK-4 的 `listModal.open` 一致，`list.js` 的调用处只改调用对象）：`mode`（`'create'` / `'edit'`）、`title`、`policytype`（2 / 3）、`systype`（1 / 2）、`pid`、`pname`、`description`（编辑时）、`onSaved(mode, data)`。另加 `name`（「白名单」/「黑名单」，拼标签用）、`namePlaceholder`、`descPlaceholder`（§五「占位」）。

## 五、页面行为

- **弹窗外观**：外壳照 `layout.html` `#addNewListModal` 复制（F-7），id 改 `#procmListModal`，内部元素用 `procm` 开头的 id 或 `js_procm_` 开头的类，不用 `addNewList*`；去掉公共弹窗自己的挂钩类 `secondm-hide`、`alert_drag` 和行内 `z-index`（层级照 TK-5 的三个弹窗，R-5）；按钮加 `type="button"`；`data-backdrop="static"`；放在 `list.html` 里和 TK-5 的三个弹窗在一起（F-6）。
- **文案**（照 demo F-8；斜杠前是白名单页、后是黑名单页）：
  - 标题：创建时「创建白名单」/「创建黑名单」，编辑时「编辑白名单」/「编辑黑名单」（PL-01 §五）；
  - 标签：「* 白名单名称：」/「* 黑名单名称：」、「* 系统类型：」、「描述：」；
  - 占位：名称「示例：办公区终端白名单」/「示例：挖矿程序黑名单」，描述「选填，说明这条白名单用在哪里、放行什么」/「选填，说明这条黑名单用在哪里、拦截什么」（两条占位文字写在 `list.js` 白、黑两份配置里，经 `open(opts)` 传给弹窗；`bwlistModal.js` 不写死白、黑文案）；
  - 按钮：「取消」+ 创建时「创建」/ 编辑时「保存」（demo 没有编辑弹窗，「保存」是本计划定的）；右上角叉。
  - 与 demo 不同处：demo 的系统类型是下拉框，旁边有说明「不同系统类型的进程差别很大，需分别建白名单」；本计划照 PL-01 §五 只显示文字、不放下拉框和这句说明（一期只有 Linux）。
- **字段**：名称 `maxlength="100"`（按字数，Q3；与后端按字节的差异见 F-11、Q4），描述 `maxlength="200"`（F-4）；两个输入框保留 `oninput="RsCore.validateXss(this)"`（与原弹窗一致，F-7）。系统类型只显示文字、不能改：创建固定「Linux/信创」（PL-01 §五），编辑显示这条名单自己的系统类型。
- **打开**：创建 = 空表单；编辑 = 带出原名称、原描述（用 `val()` 填，不当 HTML）。每次打开都按本次参数重填，不留上次的值。
- **提交**：名称、描述都先去掉首尾空格（沿用原弹窗的 `$.trim`）；名称为空 → 提示「请输入名单名称！」（沿用原文案），不关弹窗、不发请求。否则创建调 `createWBList`（`pname`、`description`、`policytype`、`systype`，不带进程），编辑调 `editWBList`（`pid`、`pname`、`description`）；请求回来前提交按钮置灰，防连点（F-6）。
- **成功**：弹接口给的提示 → 弹窗还是这一次打开的才关 → 调 `onSaved`，名单页刷新表格（已离开本页或白黑切换就不刷，沿用 `list.js` 的 `token` 判断）。
- **失败**：`core.js` 已经弹过「错误」+ 原因，这里不再弹（PL-01 F-12）；弹窗留着、按钮恢复，可以改了再点或取消。
- **关闭**：取消、叉、Esc 都关；关掉后清上下文。
- **离开页面**：`list.js` 的 `destroy` 调 `release()`；弹窗随页面清掉，body 上不留遮罩。
- 二次认证：不做（PL-01 Q1）。
