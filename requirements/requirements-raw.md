# 原始需求

## 核心需求
SOC 中心需要新增 「终端进程管控」功能，核心需求就是：通过进程策略和黑白名单控制终端上的进程运行。


## 流程

### 总流程
学习 -> 黑白名单 -> 审计 -> 拦截

### 操作流程
step1: SOC 中心下发进程策略（学习模式）给指定终端。
step2：终端将进程原始数据上报到 SOC 中心，聚合去重形成进程记录。
step3：管理员将进程规则（路径 + Hash）添加到白名单/黑名单。
step4：管理员将进程策略从「学习模式」修改为「审计模式」，然后下发给指定终端（不包含黑白名单），最后再将白名单（或黑名单）应用到指定终端所在的分组。
step5：当终端同时拥有进程策略（审计模式）和白名单（或黑名单）时，只告警，不拦截，同时上报审计日志。
step6：如果黑白名单有误杀，管理员可以将审计日志的进程规则添加到白名单/黑名单。
step7：如果黑白名单无误，可以将进程策略修改为「拦截模式」，然后下发给指定终端。
step8：当终端同时拥有进程策略（拦截模式）和白名单（或黑名单）时，真拦截，同时上报审计日志。
step9：如果拦截策略发生误杀，可以切换到审计模式下，然后再修正白名单/黑名单


## 关键名词
- 进程策略：开启/关闭，开启后有 3 个模式：学习模式/审计模式/拦截模式
- 进程信息：进程名称，文件哈希，进程路径
- 进程规则：路径 + 哈希
- 进程数据：学习模式下，终端上报的原始进程数据。
- 进程记录：学习模式下，终端上报的聚合去重后的唯一进程记录。
- 白名单：进程白名单
- 全局白名单：全局进程信用清单，是个 json 文件，存放在 SOC 中心，不给用户展示，在页面上看不到，路径由进程策略下发给终端，由终端自己取。
- 黑名单：进程黑名单
- 白名单进程列表，黑名单进程列表
- 审计日志：审计和拦截模式下，终端审计/拦截进程时，上报的日志。


## 业务规则
- 进程策略的 3 个模式不能并存。
- 一个终端只能有一个白名单或黑名单，不允许同时拥有黑白名单，不允许同时有多个白名单，或者多个黑名单。名单只能应用到分组，不能单独分配给终端，因此终端只会继承所在分组的那一个名单。
- 「进程管控权」页面访问权限限：
  - 只有 optadmin （level 8+10）才能看到「进程管控」菜单和页面，auditadmin 和 sysadmin 都不允许看到和进入。
  - 只有 optadmin 主账号（optadmin）可以看到「进程管理」、「白名单」、「黑名单」三个菜单，并拥有对其进行数据管理权限（对其他管理员不可见）。
  - optadmin 副账号（optadmin2)，可以看到概览页、日志页（但没有加黑、加白权限）、可以查看策略但无编辑权限。
- 进程策略学习模式下，终端负责上报进程原始信息，包括安装包和进程信息。
- 进程策略审计/拦截模式下，终端负责上报审计日志。
- 进程策略/名单 应用到分组，分组下的终端会自动继承策略/名单。进程策略也可以单独分配给终端，终端策略优先于分组策略，以终端策略为主。名单只能应用到分组，不能单独分配给终端。终端 1 从分组 A 换到 分组 B，终端 1 的策略和名单会继承分组 B 的


## 功能
- 概览：能够搜索和查看终端的基本信息，策略，白名单和黑名单。（「所在组」表示策略/名单是从分组策略/名单继承的，「分配」表示进程策略是单独分配给终端的，不是继承而来的；名单只能来自所在组，没有「分配」)
- 日志：搜索和查看审计日志，能够加白，加黑
- 策略：能够查看和修改分组和终端的进程策略
- 进程管理：能够搜索和查看终端学习模式下上报的进程信息，能够将进程规则加白，能够加黑
- 白名单：能够维护进程白名单，应用范围，能够维护白名单的进程规则
- 黑名单：能够维护进程黑名单，应用范围，能够维护黑名单的进程规则


## 白名单

### 白名单操作步骤
1. 新建空白名单，进程数：0，发布状态：--（表示白名单进程还未准备就绪，进程数=0 不允许发布，只有进程数 > 0 时才能发布）。
2. 给白名单添加进程，进程数：0 +5，发布状态：待发布（表示进程已经准备就绪，等待发布）。
3. 点击「发布」，进程数：5，发布状态：已发布（表示白名单已经准备完毕，可以下发了，但此时白名单仍未下发到终端）。
4. 选择「应用范围」（分组A/B/C），白名单会自动下发到这些分组下的终端（选应用范围相当于选择分组并自动下发白名单）；发布状态：已发布。
5. 给白名单添加进程，进程数：5 +2，发布状态：有变更，应用范围不变。（此时变更后的白名单未下发到终端）
6. 点击「发布」，进程数：7，发布状态：已发布，白名单自动下发到终端。（发布操作的第二个形态：标记白名单为已发布，且自动下发终端）
7. 进程不变，只修改「应用范围」，例如：添加一个分组 D，此时无需发布，白名单会自动下发到分组 D 下的终端。

### 白名单流程

先说我理解的核心变化：
「发布」的意思从"下发到终端"变成了"把当前进程内容定稿"；
真正下发终端的动作交给「应用范围」——选了范围就自动下发，已经有范围的名单再点发布也自动下发。
发布状态只描述"内容定稿了没有"，应用范围列描述"下发到了哪里"，两列各管一件事，这样设计是自洽的。


**最终控制规则**

| 发布状态 | 什么情况 | 发布 | 应用到组 | 删除 |
|---|---|---|---|---|
| --（灰） | 一个进程都没有 | 灰：空白名单不能发布 | 灰：先添加进程并发布 | 可 |
| 待发布（蓝） | 没发布过，有 +N | 可：标记为已发布 | 灰：先发布 | 可 |
| 已发布（绿） | 定稿了，没有待发布的增减（应用范围有或没有都算） | 灰：没有变更 | 可：选完 / 改完自动下发 | 可 |
| 有变更（橙） | 发布过，之后有 +N / -N | 可：未应用时只定稿；已应用时定稿并自动下发 | 灰：有变更未发布，先点发布 | 可 |

删除一律可点（红色）。已下发到终端的，删除后终端下次拉取策略时发现名单已经没有了，就会清掉本地名单（见下文第 3 个问题），这一点在提示里说明。


**需要你拍板的 4 个问题（括号里是我的推荐）**

1. **待发布的名单能不能先选应用范围？** 推荐：不允许，待发布 / -- 时「应用到组」灰色，提示"先发布"。顺序固定为 添加进程 → 发布 → 应用范围。

2. **「有变更」时改应用范围，新终端收到哪个版本？** 进程有变更时，只能点发布，不允许同时修改应用范围。有变更时，必须先发布，然后才能改应用范围。终端收到的一定是发布后的最新版白名单。

3. **已经下发到终端的名单怎么删？** 删除已下发终端的白名单有两个入口：一是直接删除已下发的白名单；二是改应用范围，把分组 D 从应用范围中排除。两种情况下，中心都不单独下发「删除」指令，而是把白名单从这些分组上撤下来；终端下次拉取策略时（在线终端在下次心跳，默认 5 分钟内；离线终端上线后），发现策略里已经没有这个白名单，就清掉本地的白名单。因此，白名单即使被引用了也可以删除。

4. **发布后进程数会变成 0 的情况** ：比如已发布的名单 6 -6，按规则是「有变更」能发布，但发布后进程数为 0、终端上等于收到一份空名单。（已发布/有变更的白名单，不允许将进程删除成 0，至少保留一个进程，删最后一个进程时阻断删除操作并给用户提示，发布按钮时事后，删除进程也要校验。进程=0 的白名单不允许发布。）


- 白名单发布状态：用于表示白名单及其进程规则是否准备就绪，与是否下发终端无关。
  - --：空白白名单，进程数=0，此时白名单不能发布。
  - 待发布：表示进程已经准备就绪，等待发布。
  - 已发布：表示白名单已经准备完毕，可以下发了，只有已发布的白名单，才能选应用范围。
  - 有变更：自从上次发布后，白名单进程有变更，需要重新发布。
