# update-current-status — 更新当前状态

## 核心原则

`CurrentStatus.md` 是项目**当前事实快照**，不是修改日志。它要让新 Agent 在 1～2 分钟内答出：

1. 项目现在处于什么阶段；
2. 哪些文档 / 阶段已经通过，哪些还没有；
3. 当前正在做什么，从哪里继续；
4. 当前有哪些阻塞或待确认事项；
5. 下一步按什么顺序做；
6. 继续工作要打开哪些权威文件。

更新动作只能是按主题**新增、替换、移动或删除当前状态**，禁止在文件里反复追加任务流水。
文件不存在时用 `assets/CurrentStatus.template.md` 建骨架。

各类资料的分工（不混写）：

| 资料 | 唯一职责 |
|---|---|
| `CurrentStatus.md` | 当前事实、当前检查点、当前阻塞和下一步 |
| `changelog/` | 一次修改做了什么、为什么、怎么验证、边界是什么 |
| `review/` | 审查发现的问题、修正轨迹 |
| `insights/` | 跨任务可复用的经验和坑 |
| `requirements/`、`architecture/`、`demo/` | 需求、设计、页面演示正文 |
| Git 历史 | 已废弃方案和历史追溯 |

## 固定结构（顺序不得改变，检查脚本按此校验）

1. `当前结论`：5～8 条，只写当前阶段、唯一基线版本、已通过的关键环节、未通过的边界。不展开设计正文、审查过程。
2. `阶段与文档状态`：表头固定 `| 项 | 状态 | 当前依据与边界 |`，**每一项只许一行**。
   状态值只能用 `PASS` / `FAIL` / `BLOCKED` / `IN_PROGRESS` / `NOT_STARTED` / `READY`，
   禁止「基本完成」「应该可以」「原则通过」这类模糊说法。
   设计定稿、编码实现、101 联调、客户验收要分开写，不能互相冒充。
3. `当前进行中`：最多 3 项，每项写清对象、当前检查点、当前结论、下一动作、恢复入口（指向 changelog/review）。
   同一任务推进时覆盖原条目；结束后移除，最终结果写进第 2 节或阻塞项。
4. `阻塞项与待确认事项`：只留仍会改变后续行动的事；每项写影响范围、是否阻塞当前工作、关闭条件、下一动作。关闭的直接删，不留删除线。
5. `下一步`：最多 5 项，编号列表，按真实执行顺序。不得含已完成、已取消、删除线或「以后可能考虑」。
6. `最近 3 个自然日摘要`：**只放一行指针**，照抄模板那一行；不得出现 `### YYYY-MM-DD` 日期标题（脚本发现即 FAIL）。
7. `当前权威入口`：继续工作必须用的需求、设计、demo、协议、数据库脚本、源码位置；只做导航，不抄正文。
8. `仓库现场`：最后核实时的分支、HEAD、是否有未提交修改；并注明开工仍须实时跑 `git status --short --branch`。

文件结尾固定两行（`TZ` = `date +%Z`，时间一律用 `date` 当场取）：

```text
最后更新：YYYY-MM-DD HH:mm TZ
最后精炼：YYYY-MM-DD HH:mm TZ
```

体量：目标不超过 150 行 / 15 KiB；超过 200 行 / 20 KiB 必须清理（`clear-current-status`）。

## 触发判断

以下情况必须更新：

- 项目阶段变化（如设计 → 编码）；
- 某项文档 / 阶段进入进行中，或变为 PASS / FAIL / BLOCKED；
- 当前任务的检查点、恢复点或下一动作变化；
- 新增、关闭或改变阻塞项 / 待确认事项（如设计文档 12.1 的 P 系列有了答复）；
- 用户、产品、项目负责人或领导拍板了影响后续工作的决定；
- 权威入口（需求、设计、demo、协议、脚本）的版本或位置变化；
- 审查 / 自检循环完成一轮或异常中断，需要保存恢复点；
- 发现状态页与权威文件、现场或 Git 冲突。

不更新：普通问答、无新结论的只读调查、临时重试、只改排版或错别字、同一状态没有语义变化。

## 真值优先级（冲突时按此核实）

1. 现场和可重复运行的证据（101 环境实测、SOC 源码实查）；
2. 当前权威文件：`requirements/`、`architecture/`、`demo/`、`others/`；
3. 当前 Git 文件和工作区状态；
4. `CurrentStatus.md`；
5. changelog / review 历史。

不得修改权威文件去迁就状态页；状态页过期就改状态页。
例外：「当前进行中」给出了 changelog/review 恢复入口时，以该入口里最新一轮和时间戳为准。

## 前置闸门：并行工作区禁写（先做，不通过就别往下走）

状态页是「项目当前唯一事实」，**不允许在 `git worktree` 拉出来的并行工作区里更新**——
两条线各写一份，合并冲突事小，产生两个互相矛盾的「当前」事大。
本项目目前不用并行工作区，但 Claude 桌面版可能把会话开在独立工作区里，所以闸门保留。

**判定用命令，不靠自我感觉**（`cd` 到状态页所在目录原样跑，勿改写成 `git -C`）：

```bash
[ "$(env -u GIT_DIR -u GIT_WORK_TREE -u GIT_COMMON_DIR git rev-parse --git-dir)" -ef "$(env -u GIT_DIR -u GIT_WORK_TREE -u GIT_COMMON_DIR git rev-parse --git-common-dir)" ] && echo "主工作区" || echo "并行工作区"
```

> 不要用 `--path-format=absolute`：它要 git ≥ 2.31，而 `git rev-parse` 对不认识的选项
> **原样打印且返回 0**，老 git 上会把选项本身当成路径回显，导致主工作区被误判成并行区。
> 上面的写法只用 git 2.5+ 就有的 `--git-common-dir`，`-ef` 还能自动处理相对路径与符号链接；
> `env -u GIT_*` 防外部导出的变量让 git 回答另一个仓库。
> 判据须与 `scripts/check_current_status.py` 保持同语义，改一处同步另一处。

输出 `并行工作区` 时：

1. **不要更新 `CurrentStatus.md`**；把进展写进 `changelog/` 或 `review/`。
2. 告诉用户：状态页只在主工作区更新，需要更新请回主工作区做。
3. **例外只有一个**：用户明确指令要就地更新时，检查脚本加 `--allow-worktree`，
   该跳过会在输出里留 `WARN` 痕迹。**不得由执行者自行决定使用它。**

> 检查脚本已内建同一判据（`RESULT=FAIL`），即使跳过本节也会被拦下；
> 但那时文件已被改动，**本节的价值是改之前就停手**。

## 执行流程

1. 完整读取 `CurrentStatus.md`。
2. 读取本次变化对应的权威文件或现场证据；不要把口头声明或 changelog 直接当作当前事实。PASS、FAIL、BLOCKED 都必须能定位到可复核证据；BLOCKED 至少写清尝试对象、阻塞类别、影响范围和恢复条件。
3. 对每一条「当前进行中」的恢复入口，读取其指向的 changelog/review，以其中最新轮次和时间戳校验状态页。
4. 执行 `git status --short --branch` 与 `git diff -- CurrentStatus.md`，保护既有未提交修改。
5. 提炼「状态差异」，不要抄文件 diff、命令输出或完整审查意见。
6. 在固定章节中更新同一主题：
   - 新事实才新增；
   - 状态变化直接替换；
   - 任务完成时删除进行中项，更新第 2 节（最近修改历史由 `changelog/INDEX.md` 承担，不在状态页写摘要）；
   - 阻塞关闭时删除阻塞项；
   - 下一步变化时删除或重排旧项。
7. 每一项状态、当前任务和阻塞只保留一个当前版本。
8. 确认「最近 3 个自然日摘要」一节仍只有一行指向 `changelog/INDEX.md` 的指针。
9. 用 `date '+%Y-%m-%d %H:%M %Z'` 取时间，更新末尾「最后更新」；普通更新不改「最后精炼」。
10. 有持久化改动或新证据时，复用本任务已有 changelog；没有则用 `update-changelog` 新建。仅因同步状态页本身，不新建重复日志。
11. 运行：

    ```bash
    python3 .claude/skills/update-current-status/scripts/check_current_status.py CurrentStatus.md
    ```

12. `RESULT=PASS` 只表示结构与可机械发现的问题通过；仍须完成第 3 步的语义对账。`RESULT=CLEAR_REQUIRED` 时同回合使用 `clear-current-status`；`RESULT=FAIL` 时先修结构或链接。

## 禁止写入

逐轮审查意见、完整修改清单、命令和日志输出、需求 / 设计正文、已废弃方案推演、已完成事项的删除线、被新事实取代的旧结论、密码 / token / 带凭据的命令（凭据只在 `CLAUDE.local.md`）、「见顶部」「已由上方取代」这类依赖旧结构的文字。

## 完成门

- 新 Agent 不读 changelog 也能说出当前阶段、阻塞和下一步；
- 同一主题没有新旧状态并存，第 2 节每项只出现一次；
- 「最近 3 个自然日摘要」一节只有指向 `changelog/INDEX.md` 的指针；
- 下一步没有已完成事项；
- 本地链接有效；
- 没覆盖其他人的未提交修改；
- **不在并行工作区更新**（前置闸门已判定；用 `--allow-worktree` 跳过时，必须能指出用户的明确指令出处）；
- 检查脚本返回 `RESULT=PASS`。
